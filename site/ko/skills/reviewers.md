# 명세 리뷰어 게이트 (Spec Reviewers)

명세 리뷰어 프로토콜 (`skills/references/reviewers.md`)은 `design` 단계에서 `plan`으로 전달되기 전에 실행되는 병렬 리뷰 게이트를 규정합니다.

## 트리거 기반 동적 선택

명세서의 특성에 따라 리뷰어가 동적으로 선택됩니다:

| 트리거 조건 | 실행되는 리뷰어 | 검토 역할 |
|---|---|---|
| 항상 (기준선) | `spec-compliance` | 계약의 완결성, 명확한 테스트 기준, 비서사적 서식 검증. |
| 상태 전이 / 비동기 흐름 | `state-machine` | 상태 머신 완결성, 불법 상태 전이, 타임아웃, 레이스 컨디션 검증. |
| 교차 규칙 / 다중 명세 | `cross-rule` | 시스템 규칙, 기존 명세, 불변 조건 간의 일관성 검증. |
| 모듈 / 리포지토리 교차 | `cross-module` | 계약 경계, Schema 호환성, 의존성 순서 검증. |
| 크래시 / 복구 / 영속성 | `safety` | 크래시 복구, 데이터 손실 방지, 멱등 재시도, 롤백 안전성 검증. |
| 구현 복잡도가 높은 경우 | `implementability` | 견적 범위 내에서 작업을 명확히 실행할 수 있는지, 암묵적 모호함이 없는지 평가. |

## 병렬 실행 및 Coordinator 통합 평가

1. **병렬 실행**: 트리거된 모든 리뷰어가 독립적인 서브에이전트로 병렬 실행됩니다.
2. **Coordinator 통합 평가**: 주 에이전트가 지적 사항을 비판적으로 평가하고, 충돌 해결, 누락 조치, 심각도 판정을 수행하여 한 번의 패스로 명세서를 수정합니다. 리뷰어는 조언을 제공하고 Coordinator가 최종 결정을 내립니다.
