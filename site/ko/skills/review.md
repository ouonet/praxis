# review

`review` 스킬은 병합 전, 서브에이전트 작업 완료 후 또는 명세·계획 리뷰 시 실행됩니다. 멀티 모듈 작업에서는 각 모듈 소속 리포지토리의 diff를 먼저 검토한 뒤 워크스페이스 전체 변경 집합을 검토합니다.

## 8가지 점검 항목

우선순위 순서대로 확인합니다:

1. **명세 일치**: diff가 스테이징 명세 및 계획대로 구현되었고 누락된 드리프트가 없는지 확인.
2. **표준 준수**: lint/format/typecheck가 통과하고 코드가 `convention:`에 부합하는지 확인 ([품질 표준](./quality)).
3. **테스트**: 새 동작과 엣지 케이스가 테스트로 보호되며 모두 통과하는지 확인.
4. **문서 커버리지 및 라이빙 문서**: `contract`가 전체 공개 표면을 포괄하고 설정/오류 모드가 문서화되며 `README.md` 명령이 실행 가능하고 라이빙 문서가 비시계열·모듈형 원칙을 지키는지 확인.
5. **엣지 케이스**: null, 빈 값, 대용량, 동시성, 잘못된 형식, Unicode, 시간대 처리.
6. **보안**: 입력 검증, 시크릿 보호, 인가 경계, 인젝션, 경로 순회.
7. **범위**: 무관한 변경은 되돌리고 필요 이상의 과도한 복잡성(>2x)은 지적해 단순화.
8. **통합 (멀티 모듈)**: 의존성 순서, 호환성, 실패 전파 및 Coordinator 통합 수용 테스트가 참여 모듈 전체를 검증하는지 확인.

## 출력 형식

결과는 `BLOCK`(병합 전 반드시 수정), `FIX`(수정 또는 사유 명시 후 연기), `NIT`(선택적 개선) 형식으로 보고합니다.
