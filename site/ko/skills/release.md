# release

`release` 스킬은 사용자가 명시적으로 릴리스, 버전 업데이트, 태그 생성 또는 배포를 요청한 경우에만 실행합니다.

`topology=multi-module`에서는 통합 검증을 통과한 정확한 Coordinator revision set만 리포지토리 의존성 순서에 따라 릴리스합니다. 변경 작업 완료 자체가 릴리스를 승인하지는 않습니다.

## 릴리스 절차

1. 목표 시맨틱 버전 증가(`MAJOR.MINOR.PATCH`)를 확인합니다.
2. 테스트가 모두 통과하고 작업 트리가 깨끗한지 확인합니다.
3. 단일 버전 소스에서 모든 버전 관리 대상 매니페스트를 일관되게 업데이트합니다.
4. `CHANGELOG.md`의 `Unreleased` 항목을 `<version> - <date>`로 옮기고 새 `Unreleased` 섹션을 복원합니다.

`<gate>`
5~7단계는 공유 상태 또는 되돌릴 수 없는 상태를 변경하므로 **각 단계 실행 전마다 개별적으로 사용자의 명시적 승인을 받아야 합니다** (한 번의 승인으로 연쇄 실행 금지):
`</gate>`

5. 릴리스 편집 내용을 커밋합니다.
6. 주석 달린 Git 태그(`v<version>`)를 생성합니다.
7. 커밋/태그를 push하거나 패키지를 게시합니다.
