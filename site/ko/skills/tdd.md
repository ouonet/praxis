# tdd

`tdd` 스킬은 계획 승인 후 엄격한 RED → GREEN → 리팩터링 사이클과 문서 동기화를 통해 구현을 진행합니다. 멀티 모듈 변경에서는 구현과 로컬 수용 검증을 작업 소속 리포지토리에서 수행하며, Coordinator는 공유 계약 실체 또는 워크스페이스 상태에 대해서만 업데이트합니다.

## 수용 모드

현재 작업의 `acceptance:` 필드에 따라 모드를 선택합니다:

- **자동 수용(Automated)**: 먼저 실패하는 검사(올바른 이유로 실패하는 RED) 없이 프로덕션 코드를 작성할 수 없습니다. RED → GREEN(최소 구현) → 리팩터링 → 문서 동기화 → 커밋 → `- [x]` 순으로 진행합니다.
- **수동 수용(Manual)**: 설정·문서·인프라·콘텐츠 등 자동 테스트가 없는 산출물은 명시된 수동 검증 절차를 수행하고, 변경을 최소화하며, 기계적 검사와 문서 동기화를 완료한 뒤 `- [x]`로 표시합니다.
- **수용 기준 없음**: 프로덕션 코드를 작성하기 전에 사용자에게 확인합니다.

## 문서 동기화 및 완료 표시

- 통과 후 `docs/staging/specs/*.md`를 실제 코드 동작에 맞게 업데이트합니다 (스테이징 명세가 없는 `small` 작업은 라이빙 문서를 직접 업데이트).
- 다음 작업으로 넘어가기 전에 반드시 `docs/staging/plans/YYYY-MM-DD-<topic>.md`의 `- [ ]`를 `- [x]`로 변경합니다.
- 연결된 다중 리포지토리 변경은 Coordinator 통합 테스트가 통과할 때까지 커밋을 보류한 뒤 의존성 순서대로 커밋합니다.
