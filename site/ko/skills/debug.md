# debug

`debug` 스킬은 추측에 의존하지 않고 결정론적 근본 원인 규명을 통해 버그, 회귀 및 예기치 않은 실패를 격리·수정합니다.

`topology=multi-module`에서는 참여 리포지토리 전반을 읽기 전용으로 조사하고, 수정은 작업에 등록된 소속 모듈 리포지토리 내에서만 수행하며, Coordinator 통합 검증이 통과할 때까지 연계 커밋을 보류합니다 ([멀티 모듈 프로토콜](./multi-module)).

## 디버깅 절차

1. **재현**: 최소한의 결정론적 재현 사례를 먼저 확보합니다. 재현 불가 → 수정 불가.
2. **근본 원인**: 단일 원인이 **모든** 증상을 설명할 때까지 "왜"를 반복합니다. 한 번에 하나의 변수만 바꾸고, 세 번 가설이 실패하면 중단하고 처음부터 코드를 다시 읽습니다.
3. **TDD 수정**: 실패하는 회귀 테스트를 먼저 작성(RED)한 뒤 근본 원인을 수정해 통과시키고(GREEN) 전체 테스트 통과를 확인합니다.

완료 조건 = 결정론적 재현 + 먼저 실패 후 통과하는 회귀 테스트 + 명확한 근본 원인 규명 + 전체 테스트 그린.
