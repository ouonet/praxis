# debug

`debug` スキルは、推測に頼らず決定論的な根本原因の特定によってバグ・デグレ・テスト失敗を隔離・修正します。

`topology=multi-module` の場合は、関連リポジトリを横断して読み取り専用で調査し、修正はタスクに登録された所属モジュールリポジトリ内でのみ実施し、Coordinator 統合テスト通過まで連動コミットを保留します（[マルチモジュールプロトコル](./multi-module)）。

## プロセス

1. **再現**：最小限の決定論的再現手順を確立する。再現できなければ修正しない。
2. **根本原因特定**：単一の原因が**すべての**症状を説明できるまで「なぜ」を繰り返す。変数は1回に1つだけ変更し、3回仮説が外れたら最初からコードを読み直す。
3. **TDD 修正**：まず失敗する回帰テストを書き（RED）、根本原因を修正して通し（GREEN）、全テスト通過を確認する。

完了条件 = 決定論的再現 + 先紅後緑の回帰テスト + 根本原因の明示 + 全テストグリーン。
