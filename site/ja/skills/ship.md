# ship

`ship` スキルは、すべての計画タスク完了・テスト通過後に、全体レビュー、ロードマップ更新とアーカイブ、変更履歴の記録、および仕上げ方法の確認を統括します。

## Ship 前ゲート

次のいずれかが未達の場合は即座に停止します：

- 自動テストがすべて通過している（または手動受入タスクの検証が完了している）。
- 関連計画ファイルに未完了の `- [ ]` タスクが残っていない。
- ステージング仕様書が実際のコード動作を反映している。
- `README.md` のコマンドが実行可能であり、リビングドキュメントが Living Doc North Star（[品質標準](./quality)）を満たしている。
- ハーネスのタスクトラッカー上に未完了タスクが残っていない。
- マルチモジュール作業では全モジュールの受入と Coordinator 統合受入が完了している（または `partial-commit` 回復状態として報告されている）。

## Ship 手順

1. 全体の diff に対して `review` を実行する。
2. `docs/ROADMAP.md` を更新する（完了マイルストーンを `[x]` に変更し、必要に応じて後続スタブを調整）。
3. `archive` を実行する（マルチモジュール時はモジュールリポジトリを先に、Coordinator を最後にアーカイブ）。
4. ユーザーに影響する変更があれば `CHANGELOG.md` の `Unreleased` に追記する。
5. 仕上げ方法をユーザーに確認する（**commit / merge / PR / keep / discard**）— 明示的承認なしに push や PR 作成は行わない。
6. マージや PR 後は worktree とローカルブランチを清掃し、未完了マイルストーンがあれば次の `plan` へ進む。
