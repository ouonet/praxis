# plan

`plan` スキルは、承認された仕様書を `docs/staging/plans/YYYY-MM-DD-<topic>.md` の実行可能なマイルストーンタスクに分解します。仕様書への参照のみを記述し、背景・アーキテクチャ・理由は重複記述しません。

## ローリングウェーブとマルチモジュールトポロジー

- **ローリングウェーブ（Rolling wave）**：仕様書が `docs/ROADMAP.md` の `milestone: MN` を参照している場合、そのマイルストーンのみを展開し、残りは1行のスタブとして残します。`ship` 後に次のマイルストーンを確認してから展開し、目標が本質的に変わった場合のみ `design` に戻ります。
- **マルチモジュールトポロジー**：`topology=multi-module` が宣言されている場合は、[マルチモジュールプロトコル](./multi-module) を読み、Coordinator ワークスペース計画の先頭にモード宣言ブロック（`topology: multi-module`、`change-set`、`coordinator`、`repos`、各モジュール計画パス、統合タスク）を記述します。各タスクは1つの `repository:` と1つの `module:` に属し、「契約 → 利用側 → ローカル受入 → 統合 → 依存順コミット」の順に並べます。

## マイルストーンタスク（各 30〜60 分）

各タスクは見出しではなくチェックボックス（`- [ ] T<n>: <名前>`）として記述します：

```text
goal:       <1行の目的>
files:      <対象パス>
acceptance: <実行可能なテスト、コマンド、または明示的な手動検証手順>
spec:       <docs/staging/specs/...#anchor>
```

共有契約・状態・受入境界が閉じており、書き込み範囲が重複しない独立タスクのみ `[parallel] T3, T4, T5` を付けます。原子的な詳細ステップへの展開は `subagents` 派遣時まで遅延させます。

## ハンドオフゲート

`<gate>`
`tdd` または `subagents` に引き渡す前に、`docs/staging/plans/YYYY-MM-DD-<topic>.md`（マルチモジュール時は影響する各モジュールの計画ファイルを含む）がディスク上に存在し、ユーザー確認を得ている必要があります。
`</gate>`
