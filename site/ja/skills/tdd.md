# tdd

`tdd` スキルは、計画承認後の実装を厳格な RED → GREEN → リファクタリングサイクルと同期ドキュメント更新によって推進します。マルチモジュール作業では、実装とローカル受入はタスク所属リポジトリ内で実行し、Coordinator は共有契約の実態やワークスペース状態に関してのみ更新します。

## 受入モード

現在のタスクの `acceptance:` フィールドに応じて適用モードを選択します：

- **自動受入（Automated）**：先に失敗するチェック（正しい理由による RED）なしで本番コードを書いてはなりません。RED → GREEN（最小実装）→ リファクタリング → ドキュメント同期 → コミット → `- [x]` の順に実行します。
- **手動受入（Manual）**：自動テストを持たない設定・ドキュメント・インフラ・コンテンツ等のタスクでは、明示された手動確認手順を実施し、変更を最小限に保ち、メカニカルチェックとドキュメント同期を行って `- [x]` に更新します。
- **受入基準なし**：本番コードを書く前にユーザーへ確認します。

## ドキュメント同期と完了記録

- パス後に `docs/staging/specs/*.md` を実コードに合わせて更新します（ステージング仕様がない `small` タスクではリビングドキュメントを直接更新します）。
- 次のタスクへ進む前に、必ず `docs/staging/plans/YYYY-MM-DD-<topic>.md` の `- [ ]` を `- [x]` に更新します。
- 複数リポジトリの連動変更は Coordinator の統合テスト通過までコミットを保留し、その後依存順にコミットします。

## リファクタリングゲート
