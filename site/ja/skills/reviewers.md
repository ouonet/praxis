# 仕様レビュアーゲート (Spec Reviewers)

仕様レビュアープロトコル (`skills/references/reviewers.md`) は、`design` 段階で `plan` に渡す前に実行される並列レビューゲートを規定します。

## トリガーベースの動的選択

仕様の特徴に基づいてレビュアーが動的に選択されます：

| トリガー条件 | 起動されるレビュアー | 検査役割 |
|---|---|---|
| 常時（ベースライン） | `spec-compliance` | 契約の完全性、明確なテスト基準、非物語的フォーマットを検証。 |
| 状態遷移 / 非同期処理 | `state-machine` | 状態マシンの完全性、不正遷移、タイムアウト、レースコンディションを検証。 |
| クロスルール / 複数仕様 | `cross-rule` | システムルール、既存仕様、不変条件との整合性を検証。 |
| モジュール / リポジトリ横断 | `cross-module` | 契約境界、Schema 互換性、依存関係順序を検証。 |
| クラッシュ / 復旧 / 永続化 | `safety` | クラッシュ復旧、データ損失防止、冪等再試行、ロールバック安全性を検証。 |
| 実装の複雑性が高い | `implementability` | 見積もり範囲内でタスクが明確に実行可能か、隠れた曖昧さがないかを評価。 |

## 並行実行と Coordinator の統合評価

1. **並行起動**: トリガーされたすべてのレビュアーが独立したサブエージェントとして並行実行されます。
2. **Coordinator の統合評価**: 主エージェントが指摘事項を批判的に評価し、矛盾の解決、漏れの特定、深刻度の判定を行い、一度の変更で仕様書を修正します。レビュアーは助言を行い、Coordinator が決定を下します。
