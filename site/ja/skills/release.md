# release

`release` スキルは、ユーザーから明示的にリリース・バージョン更新・タグ付け・公開を求められた場合にのみ実行します。

`topology=multi-module` の場合は、統合テストを通過した正確な Coordinator revision set のみをリポジトリ依存順に従ってリリースします。変更セットの完了自体はリリースの承認にはなりません。

## リリース手順

1. セマンティックバージョン更新幅（`MAJOR.MINOR.PATCH`）を確認する。
2. 全テスト通過およびクリーンな作業ツリーを確認する。
3. 単一ソースからすべてのバージョン管理対象マニフェストを同期更新する。
4. `CHANGELOG.md` の `Unreleased` を `<version> - <date>` に移し、新しい `Unreleased` 見出しを設ける。

`<gate>`
ステップ 5〜7 は共有または不可逆な状態を変更するため、**各ステップの実行前に毎回個別の明示的ユーザー承認を得る必要があります**（1回の承認で連鎖実行しない）：
`</gate>`

5. リリース編集内容をコミットする。
6. 注釈付き Git タグ（`v<version>`）を作成する。
7. コミット／タグを push またはパッケージを公開する。
