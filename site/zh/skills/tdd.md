# tdd

`tdd` 技能在计划获批后通过严谨的 RED → GREEN → 重构（refactor）循环与同步文档来推进实现。多模块变更下，实现与本地验收在任务所属仓库内执行，仅针对共享契约或工作区状态更新协调者文档。

## 验收模式

根据当前计划任务的 `acceptance:` 字段选择对应路径：

- **自动化验收**：没有先红灯（为正确原因失败的检查）就不允许写生产代码。严格遵循 RED → GREEN（最小实现）→ 重构 → 同步文档 → 提交 → 勾选 `- [x]`。
- **手工验收**：针对配置、文档、基础设施或内容类无自动化测试的交付物，执行计划声明的手工核验步骤，保持改动最小化，运行机械化检查并同步文档后标记 `- [x]`。
- **缺失验收标准**：写生产代码前先向用户确认验收方式。

## 文档同步与完成标记

- 每次通过后同步 `docs/staging/specs/*.md` 以匹配实际代码现实（无暂存规范的小任务则直接更新现存文档）。
- 立即将 `docs/staging/plans/YYYY-MM-DD-<topic>.md` 中对应任务的 `- [ ]` 改为 `- [x]`，再启动下一项任务。
- 跨仓库关联变更需等待协调者集成验收通过后，再按依赖顺序提交。
