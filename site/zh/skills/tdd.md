# TDD（测试驱动开发）

计划批准后，每个任务执行 RED → GREEN → refactor。每个循环都是一个 git 提交。

## 红

写失败的测试。声明怎样知道任务是完成的。

## 绿

写最小的代码通过测试。完全不在乎设计。

## 重构

让代码好看。无行为改变。更新规范笔记如果发现或学到了什么。

## 同步文档

RED-GREEN-refactor 每个循环后，同步文档再提交：
- 规范存在 → 更新它来匹配现实。
- 无规范（小任务）→ 直接更新 living docs。

## 验收

每个任务 acceptance 条件必须在绿后通过。如果无法自动检查，提交前手工验证。

## Gate

**停在这里如果**：
- 测试失败。
- 验收标准无法满足。
- 代码与规范不符。

否则，继续 `ship`。
