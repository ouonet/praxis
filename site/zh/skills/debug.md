# debug

`debug` 技能用于以确定性根因定位替代猜测式试错，隔离并修复故障、回归与失败测试。

在 `topology=multi-module` 场景下，先在各参与仓库内只读排查，仅在任务登记的所属模块仓库内修复问题，并延后关联提交直到协调者集成验收通过（见[多模块协议](./multi-module)）。

## 调试流程

1. **稳定复现**：建立最小化可确定重现的用例。无法复现则不贸然修改。
2. **根因定位**：持续追问“为什么”，直到单个根因能够解释**全部**现象。每次只改变一个变量；若连续 3 次假设失败，停下来重新从头通读代码与完整报错。
3. **TDD 修复**：先写失败的回归测试（RED），从根因处修复使之通过（GREEN），并运行完整测试套件确认无回归。

完成标准 = 确定性复现 + 先红后绿的回归测试 + 明确根因说明 + 测试全绿。
