# 规范评审员关卡 (Spec Reviewers)

规范评审员协议 (`skills/references/reviewers.md`) 规定了在 `design` 阶段提交给 `plan` 之前执行的并行评审关卡。

## 触发式匹配机制

根据规范特征动态选择评审员：

| 触发条件 | 派发的评审员 | 审查职责 |
|---|---|---|
| 始终触发（基线） | `spec-compliance` | 验证契约完整性、明确的测试标准及非叙事性声明格式。 |
| 状态迁移 / 异步流程 | `state-machine` | 检查状态机完整性、非法状态迁移、超时及竞态条件。 |
| 跨规则 / 多项规范 | `cross-rule` | 验证系统规则、现有规范及项目不变量之间的一致性。 |
| 跨模块 / 跨仓库 | `cross-module` | 验证契约边界、Schema 兼容性及依赖关系顺序。 |
| 崩溃 / 恢复 / 持久化 | `safety` | 检查崩溃恢复、防数据丢失、幂等重试及回滚安全性。 |
| 实现复杂度较高 | `implementability` | 评估任务能否在预估范围内清晰执行，是否存在隐式歧义。 |

## 并行执行与 Coordinator 批判性合成

1. **并行派发**：所有被触发的评审员作为独立子智能体（Subagent）并行运行。
2. **Coordinator 合成**：主智能体对其意见进行批判性评估，解决冲突、补齐遗漏、判定严重程度，并一次性修正规范。评审员提供建议，Coordinator 做出裁决。
