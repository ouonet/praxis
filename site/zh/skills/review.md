# review

`review` 技能在代码合并前、子智能体任务完成后，或规范/计划评审时执行。多模块变更应先在各自所属仓库内审查模块 diff，再作为整体变更集审查工作区协同。

## 八维检查清单

按优先级依次检查：

1. **规范匹配度**：diff 是否准确落实暂存规范与计划，无未记录漂移。
2. **工程规范**：lint/format/typecheck 全绿，代码符合 `convention:`（见[质量标准](./quality)）。
3. **测试覆盖**：新增行为与边界条件有测试覆盖且全部通过。
4. **文档覆盖率与现存文档**：`contract` 覆盖完整公开接口，配置与错误模式已记录，`README.md` 命令可运行，现存文档符合 Living Doc North Star（无历史叙事、模块化拆解）。
5. **边界条件**：null、空值、大数据量、并发、畸形输入、Unicode 与时区处理。
6. **安全性**：输入校验、密钥防护、权限边界、注入与路径穿越。
7. **变更范围**：回退无关改动；若实现复杂度显著高于必要复杂度（>2x），标记问题并简化。
8. **跨模块集成**：依赖顺序、兼容性、错误传播与协调者集成测试是否覆盖准确参与模块。

## 输出格式

严格按级别输出：`BLOCK`（合并前必须修复）、`FIX`（修复或附明理由延后）、`NIT`（可选优化）。
